# User guide

[Documentation](README.md) · [Project home](../README.md) · [简体中文](user-guide.zh-CN.md)

The app does not call a model itself. The main process starts the Cursor CLI, Codex CLI, or Claude Code adapter on this machine and talks to it over the [Agent Client Protocol](https://agentclientprotocol.com) (ACP). The composer picks Cursor, Codex, or Claude. A new conversation uses that choice and remembers it. In an existing conversation, switching CLI keeps the messages already on screen and starts the next message as a new session on the CLI you picked, sending the existing conversation along as context until that session's first turn completes. The sidebar marks each one Cursor, Codex, or Claude.

## Working with projects

1. Add a project folder. The agent works in that directory, or, for a new conversation, in that conversation’s own worktree. Removing a project deletes it from this app only. Files on disk stay.
2. On the home screen, pick the project, type a task or use one of the example prompts, choose a model and mode, and send. The three most recent conversations in that project are listed under the composer.
3. Manage conversations in the sidebar: pin, archive, rename (double-click the title), fork, sync from CLI storage, copy the session id, or delete. Syncing replaces the transcript shown here. Codex restores per-turn tokens and available durations from its rollout log. Other CLIs may drop duration and token records stored only by this app.
4. Open the changes panel to review edits, or open the working directory in VS Code, Cursor, or the file manager. Editor buttons use the conversation's actual working directory, including its worktree. After a task finishes, the conversation lists the files changed in that turn. Click a file name to expand the diff.

In the three changes-panel tabs, **Conversation edits**, **Snapshot diff**, and **Git diff**, binary files appear in a **Binary files (N)** group at the bottom of the list. The group starts collapsed, including the file names. Click its heading (or focus it and press Enter or Space) to show the names; activate it again to collapse. The file total and line-change statistics always include these files. Each tab remembers its expansion state while the panel is open, including across refreshes. Selecting another snapshot turn collapses its binary group. Switching conversations or reopening the panel collapses the group again.

The changed-file list below each conversation reply uses the same binary group and hides binary file names by default. Each turn can be expanded or collapsed independently, and its file total and line-change statistics always include binary files. Text files remain listed directly; click a file name to view its diff.

The **Collapse all projects** button beside the Projects heading collapses every project and remembers that state after a restart. The open conversation remains on screen. Click **Unread** above Settings to open unread conversations, most recently updated first. This includes archived conversations across all projects and includes running conversations waiting for your answer; other running conversations are excluded. Each jump clears sidebar search, expands the target project, and reveals and scrolls to its conversation, including one beyond the first six entries. An archived target appears temporarily while you view it; the Show archived preference stays as configured. History must load successfully in the focused, visible window before the conversation is marked read. Failed loads remain unread and can be retried.

Click **In progress** beside Unread to cycle through running conversations across all projects, including archived conversations and those waiting for your answer, most recently updated first. From a running conversation, the next click opens the next one and wraps to the first at the end; a single target reopens itself. It uses the same sidebar search clearing, project expansion, and scroll positioning as Unread. Opening a conversation waiting for your answer marks it read once its content is loaded in the visible, focused window, even before you answer. Other running conversations are not marked read. Each button is disabled when its count is zero; both buttons are disabled while either jump is loading or all projects are being collapsed. Failed jumps show an error and allow another attempt.

### Header buttons and commands

On the desktop, drag the blank space, project name, or non-interactive badges in the conversation header to move the window. Double-click the conversation title to rename it. The title, editing field, and toolbar buttons remain interactive and do not drag the window.

On the desktop, **Settings → Appearance and history → Toolbar buttons** controls the visibility and order of Fork, File manager, VS Code, Cursor, Changes, and your custom commands. Use the up/down buttons to reorder them. Actions that do not fit in the header appear in its More menu. Configuration is saved globally and restored after restart.

Add a command by entering its name, executable path or command name on PATH, and one argument per nonempty line. Arguments are literal values: do not add surrounding quotes to paths containing spaces. `{cwd}` expands to the conversation's actual working directory, and `{projectPath}` to the original project folder. Both placeholders work in the program and its arguments. For example, use program `git` and argument `status` to inspect the active worktree. To run a script, enter its interpreter as the program and the script path as an argument.

Commands run in a new terminal with the conversation directory as the working directory. Output and the exit code stay visible until you press Enter. Windows uses PowerShell, macOS uses Terminal, and Linux looks for `x-terminal-emulator`, `gnome-terminal`, `konsole`, then `xterm`; install one if none is available. Startup errors are shown in the app, and errors after launch appear in the terminal. If startup cannot be confirmed within 10 seconds, check the terminal before retrying. Header configuration and custom-command execution are available only on the desktop; remote pages follow the configured builtin action visibility and order.

Project model choices are independent for Cursor, Codex, and Claude. Changing one CLI's selection or favorites preserves the other CLIs' remembered models.

The model picker also remembers each model's context length, reasoning effort (including Thinking), and Fast setting separately for each CLI. Claude stores context and effort as separate parameters, for example `opus[context=1m,effort=high]`. Cursor variant ids such as `grok-4.7[context=500k,reasoning_effort=high,fast=true]` are applied the same way after the session starts. Passing that id to `--model` makes the CLI reject it and print its model list. Choosing Auto in an existing Cursor conversation selects `auto` on the session, so it does not keep the previous model; if the CLI cannot switch back, that message fails with an error and the next one starts a new CLI process in Auto. Codex keeps a standard id such as `gpt-5.4[high]`. A model that advertises fast mode also offers `gpt-5.4[reasoning_effort=high,fast=true]`; the session then sets the base model, reasoning effort, and the adapter's `fast-mode` option to `on` or `off`. A bare alias whose `[1m]` sibling is listed is labeled 200K. Older saved ids such as `sonnet[high]` and `opus[1m][high]` still select the same model and effort. Options are saved as soon as you select them, without sending a message. Switching back to a model restores its options, including after an app restart; choosing a favorite model, starting a new chat, switching project or CLI, and the default model in Settings all use the model's latest saved options rather than the older variant stored with the project or default. Preferences live in `state.json` and are shared with the remote page. Existing conversations keep their selected variant, and opening an older conversation does not overwrite these preferences. If a saved combination is no longer offered by the CLI, the picker selects an available variant. Hovering the model button, a model in the list, or a favorite in Settings shows that model's public API price in USD per million tokens, including Fast and long-context rates when published. Auto and models without a listed price show as unpriced.

Opening or refreshing a conversation keeps streamed messages that arrive while history is loading. Syncing an empty CLI transcript preserves the local conversation. Deleting a conversation, changing CLI configuration, or quitting also stops a CLI process that is still preparing the saved session.

The Git tab compares against the working files, including edits made after staging in a repository with no commits yet. Diff views preserve content that resembles patch headers, such as SQL `--` comments, and keep file grouping and added/deleted line counts correct.

Markdown code blocks labeled `mermaid` render as diagrams, including in saved conversations and the remote interface. Diagrams follow the light/dark theme, with **View source** and a copy button for the original Mermaid text. While a diagram is loading or if its syntax cannot be rendered, the source stays visible.

Throughout the desktop app, select text and right-click to choose **Copy**, or right-click in chat and other editable fields to choose **Paste**. Text is inserted at the cursor or replaces the selection. Pasting a screenshot into the composer adds an attachment without sending the message. These application menus are desktop-only; remote pages keep their existing browser behavior.

The composer picks the CLI, the mode, and the model, and can turn on full access (`--force`). On the home screen the CLI applies to the new conversation. Inside a conversation, switching CLI keeps the transcript already shown and starts the next message as a new session on that CLI, carrying the existing conversation over as context. The same choice is saved as the default under Settings → CLI. Full access lets the CLI run commands without confirming each one. For Claude, full access is `bypassPermissions`; Agent without it is `acceptEdits`, so file edits are accepted and commands still ask. Ask mode stays on Claude's default permission mode and the app rejects edit and command prompts. Sandbox (`--sandbox`) is a default under Settings → Defaults: follow the CLI, enabled, or disabled. It applies to Cursor. It is not a composer toggle, and Claude does not use it. On the home screen, a new conversation can also switch between the project directory and an isolated git worktree. Cursor uses `--worktree`, then continues in the directory the CLI reports. For Codex and Claude the app creates the worktree itself, so the project must be a git repository with at least one commit.

In a conversation, typing `/` opens a command menu. Arrow keys move through it, Enter or Tab selects, and Esc closes the menu without stopping a run. `/fork` forks locally. A command that takes input is inserted as `/name ` with its hint under the box; Enter then sends it. Commands with no input run immediately. The list also includes whatever the CLI sends in ACP `available_commands_update`. The first `/` in a conversation that already has a CLI session loads that session so those commands can appear. A new conversation and the home screen do not start the CLI. They reuse the last command list that CLI announced, kept on this machine, and the menu stays hidden until a list exists. The next real session refreshes that list. Text that starts with `/` and matches nothing is still sent as a normal message.

While the agent works, you can keep typing follow-ups. Enter adds the draft, with its attachments, to the conversation's queue above the composer; you can queue several. Drag a row by its handle to reorder it. Each row can be edited (it moves back into an empty composer), sent now, or deleted. When a turn ends normally, the next queued message is sent automatically, in order. Ctrl+Enter (⌘+Enter on macOS), or **Send now** on a row, stops the current turn and sends that message first; the rest of the queue continues after it. Stopping a run, a failed turn, or a queued message that cannot be sent pauses the queue. A failed message returns to the front of the queue with the error. Click **Send now** on any row to continue. `/fork` cannot be queued. The queue is kept by the desktop app, so other windows and remote pages show the same queue. It is not saved when the app quits.

With full access off, tool permission requests show a choice card and wait for an explicit allow or reject decision. Skipping or stopping does not grant permission. Claude can also require explicit confirmation for operations that its adapter excludes from full access; these requests still show a card.

## Quitting the app

If any conversation on this machine is starting, running, or waiting for a permission decision or an answer, quitting asks you to confirm. Choose **Cancel** to keep the app open and the conversations running, or **Stop conversations and quit** to stop them and exit. With no unfinished conversations, the app quits directly. Tasks started through the remote page receive the same protection; closing that page leaves the host app running.

On macOS, closing the window keeps the app and its conversations running in the background. Confirmation appears when you quit the app.

## Attachments

Use the + button in the composer, drop files into it, or paste an image from the clipboard. Remove files from their cards before sending. Each file can be up to **10 MiB**; one message can contain up to **10 files** totaling **20 MiB**. Failed uploads and rejected sends keep the draft, and completed uploads are reused on retry.

Cursor, Codex, and Claude receive PNG, JPEG, WebP, and GIF images as native image inputs. Other formats, including PDF, Office documents, code, and SVG, keep their original bytes; the agent receives a path to a local copy and uses its file tools to read it. File reads follow the CLI's permissions. Claude Ask can show a read permission card only for the exact managed attachment being read; it keeps its existing restrictions for other tools.

Copies live in the app's `data/attachments` directory, separate from transcript JSON and the project. History cards preview images and download originals; desktop file cards can open their default application. App-owned attachment references survive restarts, CLI synchronization, and forks. Deleting a conversation preserves files still used by a fork, and removes originals after their last conversation reference is deleted. Unreferenced uploads expire after 24 hours and are cleaned on startup or the next upload. Imported CLI history without a trusted local binding shows an unavailable-attachment placeholder.

Question replies and Run plan send only their own text, leaving draft attachments in the composer. Selecting a CLI slash command with files fills the input without sending immediately; remove attachments before using the local `/fork` command. A fallback fork sends its historical image bytes again; if those images and the new message exceed the per-message limits, reduce the selected history before retrying.

## Appearance and history

Open **Settings → Appearance and history** and switch between **Appearance / Toolbar buttons / History**. Appearance groups interface and typography settings, with visual theme choices and a live text preview. Toolbar buttons has its own page for ordering actions and editing custom commands. History contains archived chat visibility and CLI session import. Remote pages show only Appearance and History.

## Skins and animated backgrounds

Open **Settings → Appearance and history → Appearance → Skins**. Choose Default, Frost or Aurora, or adjust background/panel/text/accent colors, panel opacity (0–100%), blur (0–40 px), background dimming, and image/video scaling. Colors inherit the light/dark/system theme until overridden. Edits preview immediately; **Apply skin** persists them, **Cancel preview** or leaving the appearance page restores unapplied changes. **Save as new skin** creates a named preset; applying changes to an existing custom skin updates it. Built-in skins cannot be deleted. Restore default previews the original appearance; apply it to keep the change.

On desktop, select an image (PNG/JPEG/WebP/GIF/BMP/SVG), MP4/WebM video, Web project folder, HTML entry, or Wallpaper Engine `project.json`. Videos loop silently; codec compatibility depends on Electron. Use **Refresh Wallpaper library** to discover Steam libraries on Windows, including downloaded Workshop items and local/default projects. Add a library/project folder manually on any desktop platform. Search/filter the results and select an available video or Web wallpaper. Scene, application, malformed and missing projects show a reason and cannot be selected.

Wallpaper Engine does not need to keep running. Assets reference their original files: moving/deleting files or unsubscribing from a Workshop item may break the reference. **Choose file / Relocate** or **Choose Web project** selects a replacement. Removing a reference or deleting a skin never deletes the original files. Failed backgrounds fall back to the theme color, with a reload button and a settings hint.

Web wallpapers run in an isolated frame without the app API, network access, child frames or workers. Ordinary local HTML/CSS/JS/WebGL is supported, with default and editable boolean/slider/color/combo/text properties, a 30 FPS hint and pause notifications. Color properties use Wallpaper Engine's space-separated RGB values between 0 and 1. Live audio capture/response, desktop media metadata, hardware APIs and external file/directory properties are not implemented; wallpapers requiring them may not work. When hidden/minimized the app pauses video and unloads Web backgrounds; returning reloads the Web project. Reduced-motion mode uses a preview image when available, otherwise the theme color; Aurora becomes static.

Remote browsers sync only colors, opacity and blur. They cannot manage, download or play desktop background assets. Skin configuration is stored in `data/state.json`; desktop-only file references and manually added library folders are stored in `data/skin-sources.json`. See [data storage](data-storage.md).

## Interface language

Open **Settings → Appearance and history → Appearance → Language** and choose **System**, **Simplified Chinese**, or **English**. The default is System: Chinese desktop OS locales use Simplified Chinese, and other locales use English. The preference is saved in `state.json`; desktop and remote pages share it, including the desktop OS language when System is selected. Changing the language updates the interface without restarting the app or an agent session.

Navigation, settings, dialogs, tool summaries, usage explanations, dates, relative times, and application notifications use the selected language. New application notices and automatic conversation titles keep their source identifiers so they can also change language later. User names and messages, model replies, CLI output, and older saved text without these identifiers retain their original wording.

## Font and size

Open **Settings → Appearance and history → Appearance** to change the font and font size. Choose the system default or a common font, or enter the name of a font installed on your device. If the font is unavailable, the app falls back to the system font. Font size ranges from **10 to 24 px**, with **13.5 px** as the default; interface text, chat content, the composer, and code scale together. Code keeps its monospace font.

Changes take effect immediately and are saved in `state.json` across restarts. Desktop and remote pages share these preferences; the fonts available depend on each device.

## Grok Bot

Click **Grok Bot** above **Projects** in the sidebar to chat with the [Grok Bot](https://cursor.com/docs/grok-bot) bots on your Cursor account. The left column lists your bots; choose one to read its conversation and send messages. The conversation is the same one you see in the Grok Bot app, so the bot keeps its memory and tools.

- **Bot list**: the public API cannot list bots. The list combines the roster that the Grok Bot desktop app caches on this computer (`<appData>/Grok Bot/sand-client-persistence`) with names you add under **Settings → Grok Bot**. Cached bots come first; a manual name that the cache already has is shown once. Without the Grok Bot desktop app, the manual names are still listed. Group chats and bots hidden from the Grok Bot sidebar are left out. Click refresh after you add or rename a bot in Grok Bot. Remove a manual name in Settings, or with the × on its row; this only removes it from this app.
- **New bot**: click **+** at the top of the list and enter a name. The app opens that name through the API, which creates the bot when your account has none, then adds the name to the manual list and selects it. If the list already has that name, the app asks whether to open the existing bot instead, because the API looks bots up by name and would not create a second one.
- **Authentication**: requests go to `https://api.cursor.com/v0/grokbot` with the Cursor API key from **Settings → CLI → Cursor**, or `CURSOR_API_KEY` when Settings is empty. Browser login cannot be used here. `CURSOR_API_BASE_URL` overrides the API host.
- **Messages**: only your messages and what the bot sends you are shown; the bot's internal work is not. While the bot is working, the view polls every 1.5 seconds and you can interrupt the turn. A new message can be sent only after the bot finishes. When idle, it checks for new replies every 10 seconds.
- **Loading**: switching between bots, or leaving the Grok Bot view and coming back, shows the messages you already loaded at once and only fetches what changed since. After a restart, the first visit shows messages saved on this computer and then fetches only newer entries; the bot's API session id is saved too, so the slow name lookup is skipped. A long conversation whose saved copy was trimmed loads its full history once in the background. If the saved position cannot be continued (the API rejects it, the bot was recreated, or the API key now points at another account), the view reloads the full history.
- **Names**: the API finds a bot by name. Reading, sending, and interrupting only send names in the list (cached roster plus manual names); only **New bot** sends a new name. A manual name that does not exist in your account creates a new bot the first time you open it, so enter names exactly. When two bots share a name, the view warns that the conversation may belong to either one; rename one in Grok Bot.
- **Files**: the API leaves files out of messages; a file delivery arrives without text. For bots in the cached roster, the app reads the Grok Bot desktop app's cached transcript for that bot and matches entries by sequence number, kind, and time, then looks for the bytes in `<appData>/Grok Bot/attachment-image-cache` by SHA-256 (bot files are stored under their SHA-256). Found images, including SVG, are shown through `<img>`, where SVG scripts do not run; files are never inlined as markup. Each file has buttons to save it and to show the cached file in its folder. When the bytes are not cached, a card shows the file name and asks you to download it in the Grok Bot app; recent messages are checked again while the view polls, and the card has a check-again button. Bots added by hand have no cached transcript, so their file deliveries only show this card. **This relies on the Grok Bot desktop app's undocumented local cache and may break when Grok Bot updates.** In a remote browser, previews and downloads are fetched through the remote link (up to 10 MiB per file); showing the file in its folder is desktop only.

## Plan mode

Cursor does not expose an AskQuestion tool to ACP clients. Codex Plan is a collaboration mode (`collaboration_mode=plan`); it keeps the selected Agent permission preset so that approved implementation inherits full access when enabled. The client still rejects explicit file-edit permission requests during planning. If the adapter cannot enable Plan or apply the permission preset, the turn stops with an error. Codex Plan is not Cursor’s `modeId: plan`. Claude Plan is the adapter's `plan` permission mode. All three get a short instruction in front of Plan messages, wrapped in an `<agent_desktop_client>` tag. That tag is stripped when CLI history is imported. The instruction asks the model to work like this:

- When it needs a choice, the model emits a fenced code block whose language is `questions` and whose body is JSON. The UI renders it as option cards and adds “Other (type your answer)” to every question. Selecting Other opens a multiline text field. For single-choice questions, Other replaces the selected option; for multiple-choice questions, it can be combined with existing options. Selected Other answers must contain non-whitespace text before Continue is enabled. Switching options keeps the draft, but deselected Other text is not sent. After you press Continue, your selected options and manual answers are sent together as the next message. Skip lets the model proceed on its own judgment. Only the latest round of cards can be submitted. Native ACP permission cards keep their fixed options.
- Once the requirements are clear, Cursor uses CreatePlan, and Codex and Claude emit a plan, to produce a name, a summary, and a Markdown body. The UI shows a plan card: name, summary, todos, and an expandable full plan. Cursor also offers Open plan file (`~/.cursor/plans/*.plan.md`). Codex and Claude hide that button when there is no such file.
- Run plan switches the composer to Agent mode and sends a message to implement the plan. Only the latest plan shows this button.

Codex also asks whether to implement a completed plan. This confirmation follows the app's language setting. Choosing Yes switches the current turn, saved conversation, and composer to Agent before implementation starts, preserving the full-access selection. With full access enabled, implementation commands and edits proceed without extra permission cards. Choosing No opens a multiline field for the changes you want; Continue requires non-whitespace feedback. Switching back to Yes keeps the draft but does not send it. No declines implementation, then sends your feedback as the next message in Plan mode on the same session after the current turn finishes. The submitted feedback is saved in history. Skipping or stopping does not approve implementation or send a revision. Other native ACP permission cards keep their fixed options.

Under ACP, the CLI auto-approves a SwitchMode the model starts, and it does not tell the client. If Cursor or Claude switches mode during a Plan turn, the app immediately sets the session mode back to Plan so it does not start editing files.

## Feature reference

- Multi-project sidebar: add, rename, reorder, collapse, and search conversations. Search matches the title, the preview, and the project name
- Fork a conversation from the header, the sidebar, a message, or by sending `/fork`, preserving its history as context for the next message
- Slash commands in a conversation: typing `/` lists `/fork` and the commands the CLI advertises. `/fork` runs in the app; other commands are sent as the next message
- Three modes: Agent (can edit files and run commands), Plan (read-only plan; pick answers and run the plan in one click), Ask (read-only Q&A)
- Attach images and files from the desktop or remote page by choosing files, dragging them into the composer, or pasting a screenshot. Send attachments with a message or on their own
- Markdown replies stay intact when a Codex background subagent finishes during streaming. Existing history split by these notifications is rejoined for display, including code blocks and question cards. Question prompts and options preserve line breaks.
- Replies support bold text next to Chinese punctuation and surrounding Han text, such as `这是**“重点”**内容` and `这是**重点：**内容`. Full plan bodies use the same rendering. Code, escaped asterisks, and copied message text retain their original content.
- ACP message IDs keep separate commentary and final replies from running together, so Markdown fences and question cards start correctly. On loading older Codex history, missing paragraph breaks are restored only when the original session log confirms the exact joined messages.
- Expanding a Codex command shows its output and exit code, including failed commands and saved conversations. Commands with no output say so. MCP calls show their tool name and result; a null error does not mark a successful call as failed. Older incorrect MCP labels are corrected for display, and their statuses are restored from matching native Codex records when available.
- File links in replies, including image and HTML previews, open with the desktop's default application. Windows paths, local `file:` URLs, and relative paths are supported; relative paths use the conversation's working directory, including its worktree. Failed opens show an error. On the remote page, local files open on the host desktop with a confirmation notice; web links open in the remote browser.
- Hover over any interface hyperlink to see its full destination, or right-click and choose **Copy link**. On the desktop, if text is selected, right-clicking a link offers **Copy** for that selection instead; with no selection, it offers **Copy link**. Web links display and copy the complete URL. Local file links use the decoded full path, resolved against the conversation's working directory or worktree, without source line or column suffixes. Copying a link uses the clipboard on the device viewing the app and shows a success or failure notice.
- Model picker: Cursor, Codex, and Claude each remember favorite models, a default model, and each model’s context length, reasoning effort, and Fast. Codex lists reasoning effort per model, for example Ultra on Astra, and adds a Fast variant only when that model advertises fast mode. The variant is applied as `fast-mode` `on` or `off`. Claude writes context and effort as separate parameters on the model id, for example `opus[context=1m,effort=high]`, and each model keeps the effort levels the adapter advertises for that model. Cursor applies a full variant, such as `grok-4.7[context=500k,reasoning_effort=high,fast=true]`, as separate model parameters after the session starts. Older ids such as `sonnet[high]` still resolve. Each project remembers the last model chosen for that CLI. Hovering a model shows the same public list price
- A new conversation can run in an isolated git worktree. Cursor uses the CLI's own `--worktree`, then continues the session in the directory the CLI reports. For Codex and Claude the app creates a worktree and a new `agent-desktop/<name>` branch at the project's HEAD, so uncommitted changes are not carried over
- Changes panel with two tabs: files edited in this conversation, and the git branch, status, and diff of the working directory
- Find in conversation: Ctrl+F (⌘F on macOS) opens a find bar over a conversation or a Grok Bot chat, even while typing in the composer; text selected in a message or in the composer fills it in. Search is case-insensitive and updates as you type; **Aa** matches case and **ab** matches whole words. The bar shows the current match and the total, highlights every match with the current one emphasized, and scrolls the current one to the middle. Enter / Shift+Enter, F3 / Shift+F3, or the arrow buttons move between matches. Esc closes the bar, clears the highlights, and puts focus back where it was. Only the message area is searched: the sidebar, headers, composer, buttons, and the changes panel are not. Text the view does not show is not searched either: the steps folded under “Completed · Steps: N” in finished turns, collapsed tool details, thinking blocks, and full plans. Expand them to search them; the open search picks them up. While a reply streams or Grok Bot receives new messages, the search updates and stays on the current match. In the remote web page Ctrl+F opens this bar too; on other pages the browser's own find is left alone. Highlights need a Chromium-based browser (the desktop app always has one); without the highlight feature, the bar still counts matches and scrolls to them
- Resizable panels: drag the inner edge of the sidebar, the changes panel, or the Grok Bot list to change its width. The sidebar takes 200–480 px (default 272), the changes panel 320–1000 px (default 460), and the Grok Bot list 180–400 px (default 240). Double-click the edge to restore the default width. With the edge focused, the arrow keys move it by 16 px (64 px with Shift), and Home and End go to the narrowest and widest width. When the window is too narrow, open panels shrink, the changes panel first, so the main area keeps at least 320 px; they return to the chosen width when the window grows. The desktop app saves the widths in its settings. The remote page keeps its own widths in that browser and does not change the desktop's. Below 720 px wide the narrow layout is used and the panels cannot be resized
- The file list under each reply and **Conversation edits** show only edits attributable to successful tool calls. Native per-file patches are saved independently of the workspace. A confirmed edit with only a target path is still listed with **Diff unavailable**, without guessed line counts. Previews, rejected, failed, and unfinished calls are excluded. Plain `git diff` command output is an observation, not edit evidence. Script edits without explicit per-file execution evidence are available only through snapshots. Multiple edits to a file remain in call order; line totals accumulate recorded operations rather than the workspace's net diff. Later external edits and Git commits do not rewrite saved patches.
- **Snapshot diff** is a separate changes-panel tab comparing the workspace before and after a turn, including possible edits by other applications. It follows the latest completed turn by default; **View turn** can pin a historical turn or resume following the latest. Running turns appear after completion. Successful end snapshots are also saved on interruption or process failure, even when empty. **No snapshot changes in this turn** differs from **No snapshot recorded for this turn**. There is no rescan button here; use **Git diff** for the current uncommitted workspace changes. Switching conversations or reopening the panel resets the turn selector.
- Operation records and workspace snapshots survive restarts, forks, and CLI history sync independently. Existing snapshots remain visible only in **Snapshot diff**. Legacy tool records are recovered only from explicit successful results; saved `git diff` output and current disk contents are never used to infer old edits. Tool patches are limited to 256 KiB per file and 16 MiB per turn; oversized patches retain the file entry with **Diff unavailable**, rather than an invalid partial patch.
- Git repositories use tracked and non-ignored regular files. **Ordinary directories work too, without installing Git or creating a repository**: snapshots recursively read working files, skipping version-control metadata and common dependency, cache, and build directories such as `node_modules`, `.venv`, `__pycache__`, `.cache`, `dist`, `build`, and `out`. Existing Git repositories among the first 40 name-sorted direct children retain Git ignore rules and are counted separately. Snapshots read up to 5,000 files, 256 KiB per file, and 16 MiB total; ordinary directory walks also stop at 1,000 directories, 20,000 entries, or 20 levels deep. Symlinks, submodules, and files over these limits are skipped; edit-tool diffs remain available. An incomplete initial walk never guesses that previously unseen files are new.
- When a turn finishes, the reply shows elapsed time, tokens, the model used, and a cost estimate from public list prices. Codex also shows “Turn weekly quota” with the cumulative weekly and 5-hour allowance usage attributed to that session by Codex, when available; the tooltip explains the cumulative scope. New ChatGPT-authenticated Codex turns add “Estimated turn weekly quota”, the change in the account's weekly used percentage during that turn. Missing or incomplete readings are marked accordingly. Account quota is shown in Settings → Usage
- Import CLI history from `~/.cursor/chats`, `~/.codex/sessions`, and `~/.claude/projects`, grouped into projects by working directory
- Continue a saved session with ACP `session/load`, or rebuild the transcript from CLI storage. Copying the session id lets you resume a Cursor chat in a terminal with `agent --resume`
- System notification when a task finishes; clicking it returns to that conversation. A finished run that is not on screen leaves an unread dot
- Above Settings, the sidebar shows **In progress** and **Unread** counts across all projects, including archived conversations. Each conversation counts once in each total. A new question, permission choice, or plan confirmation waiting for your answer marks its conversation unread, including while it remains in progress, and updates the unread dot, navigation, and taskbar badge. Viewing the loaded conversation in the visible, focused window clears unread even before answering; further updates to the same card do not mark it unread again, but a new question does. Markdown question cards become unread when the turn finishes. Other running conversations are excluded from unread. Success, failure, and manual stop retain the existing unread behavior. Returning to that conversation after minimizing clears its unread state; reading through the remote page also updates the desktop count.
- On Windows, unread results appear as a native taskbar overlay (`1–99`, then `99+`); zero unread clears it, and the sidebar retains the full count. Windows places this overlay at the lower-right of the icon, so its position differs from an upper-right badge. The overlay supports pinned and grouped taskbar buttons without relying on executable or shortcut icon caches. The main process updates it while minimized and when completion notifications are disabled, reapplies it when the window is shown or restored, and refreshes it every five seconds while unread results remain to recover after taskbar creation or an Explorer restart. If it is missing, check Windows **Taskbar settings → Taskbar behaviors → Show badges on taskbar apps**; small taskbar buttons do not support overlays. Display scaling and taskbar configurations still require native desktop visual checks.

Cursor models and other models also show that pool’s tokens and the account’s price. Other models uses the included API usage percent only. On-demand spend shows used and limit on the same line, and tokens when the account returns them, without repeating the price. Below that, token totals for the last 1, 7, and 30 days and a paginated list of every past session with its models and cumulative usage. Local costs use [Cursor’s public prices](https://cursor.com/docs/models-and-pricing) for Cursor, [OpenAI API prices](https://developers.openai.com/api/docs/pricing) for Codex, and [Anthropic API prices](https://platform.claude.com/docs/en/about-claude/pricing) for Claude Code. Claude is priced from the API model id recorded on the turn, not from the alias in the picker. These are usage estimates, not subscription bills. Auto, Claude aliases with no recorded API model, and models missing from the price list are shown as unpriced
