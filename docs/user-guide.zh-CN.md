# 使用指南

[文档目录](README.zh-CN.md) · [项目首页](../README.zh-CN.md) · [English](user-guide.md)

## CLI 与会话

应用本身不调用模型。主进程在本机启动 Cursor CLI、Codex CLI 或 Claude Code 适配器，通过 [Agent Client Protocol](https://agentclientprotocol.com)（ACP）与之通信。输入框可以直接选择 Cursor、Codex 或 Claude。新建对话使用这个选择，并把它记住。已有对话里切换 CLI 时，屏幕上已有的消息保留，下一条消息会用所选 CLI 新开一段会话，并把已有对话作为上下文一并发送；新会话第一轮成功结束后才不再重复附带。侧边栏会标出每一段是 Cursor、Codex 还是 Claude。

## 使用

### 切换对话与草稿

切换对话或返回首页后，再打开原对话，会恢复未发送的文字、附件，以及输入框中的 CLI、模型、模式和权限选择。首页按项目分别保留新对话草稿和 Worktree 选择。问答卡片会保留未提交的单选、多选、其他答案和计划修改意见；计划卡片也会保留展开状态。

发送或提交过程中可以切换对话，结果只更新原对话的草稿：消息发送成功后清空文字和附件，失败则保留供重试。卡片已提交的答案以会话记录为准。草稿保存在当前窗口或远程网页的内存中，刷新页面、关闭窗口或重启后不保留，也不会同步到其他窗口；删除对话或项目会清理对应草稿。

### 附件

点击输入框的 + 按钮选择文件，把文件拖入输入框，或粘贴剪贴板中的图片。发送前可在附件卡片上移除文件。单文件最多 **10 MiB**，每条消息最多 **10 个文件**，合计最多 **20 MiB**。上传失败或发送请求被拒绝时保留草稿，重试会复用已经完成的上传。

Cursor、Codex、Claude 均通过原生图片输入接收 PNG、JPEG、WebP、GIF。PDF、Office 文档、代码、SVG 等其他文件保留原始字节，代理收到本地副本路径后通过文件工具读取，沿用 CLI 的读取权限。Claude Ask 只会为正在读取的受管理附件原件展示读取权限卡，其他工具继续遵循现有模式限制。

副本存放于应用的 `data/attachments`，与消息 JSON、项目目录分开。历史卡片支持预览图片和下载原件，桌面文件卡片可以调用系统默认程序打开。本应用的附件引用在重启、CLI 同步和分叉后保留。删除源对话不会删除分叉仍在使用的文件；删除最后一个对话引用后清理原件。未引用的上传暂存文件在 24 小时后于应用启动或下次上传时清理。导入的 CLI 历史没有可信本地绑定时，显示附件不可用占位。

回答问题和执行计划只发送各自的文字，不会夹带附件草稿。有附件时选择 CLI 斜杠命令仅填入输入框，请显式点击发送；使用本地 `/fork` 前需移除附件。备用分叉会重新发送历史图片字节，历史图片与本条消息合计超过限制时，需要缩小所选历史后重试。

### 基本操作

1. 添加一个项目文件夹。Agent 在该目录中工作；新建的对话也可以改到这段对话自己的 worktree。移除项目只从本应用删除，磁盘上的文件会留下。
2. 在首页选择项目，输入任务或点一条示例提示，选好 CLI、模型和模式后发送。输入框下方列出该项目最近的三段对话。
3. 在侧边栏管理对话：置顶、归档、重命名（双击标题）、分叉、从 CLI 存储同步、复制会话 ID、删除。同步会替换这里显示的记录。Codex 会从日志恢复每轮 token 和可用的耗时；其他 CLI 可能丢失仅由本应用保存的耗时和 token。
4. 需要看改动时打开变更面板，或在 VS Code / Cursor / 文件管理器中打开工作目录。编辑器按钮使用会话实际工作目录，包括 worktree。任务结束后，对话里会列出这一轮改过的文件，点击文件名展开 diff。

点击「项目」标题旁的「全部折叠」，一次收起全部项目，重启后仍会保留折叠状态，当前查看的会话继续显示。点击设置上方的「未读」计数，按最近更新顺序逐个查看所有项目的未读会话，包含已归档会话及正在等待用户回答的运行中会话，排除其他运行中会话。跳转会清空侧栏搜索、展开目标项目、显示前六条之外的目标并滚动定位。归档目标在查看期间临时显示，不修改「显示已归档对话」偏好。历史加载成功且窗口可见、聚焦后才标为已读；加载失败时保留未读，可再次尝试。

点击「未读」旁的「正在进行」计数，按最近更新时间从新到旧循环查看所有项目中运行中的会话，包含已归档及等待用户回答的会话。当前会话正在运行时，点击跳转下一条，末尾回到首条；只有一条时重新打开该会话。跳转同样会清空侧栏搜索、展开项目并滚动定位目标，等待回答的会话在内容加载完成且窗口可见、聚焦后即标为已读，无须先回答；其他运行中的会话不会因查看而标为已读。计数为零时对应按钮禁用；任一跳转加载中或正在全部折叠项目时，两类跳转按钮均禁用。跳转失败会提示错误，之后可再次点击。

### 顶部按钮与命令

桌面端可按住对话顶部栏的空白、项目名或非交互标记拖动窗口。双击对话标题可重命名；标题、编辑输入框和工具栏按钮所在区域用于交互，不用于拖动窗口。

桌面端的「设置 → 外观与历史 → 顶部按钮」支持控制分叉、文件管理器、VS Code、Cursor、变更面板和自定义命令的显隐，用上移／下移调整顺序。顶部放不下的操作会收进「更多」菜单。配置全局保存，重启后恢复。

添加自定义命令时，填写名称、可执行程序路径或 PATH 中的命令名，参数每个非空行填写一个。参数按原文传递，含空格的路径无需额外加引号。`{cwd}` 表示会话实际工作目录，`{projectPath}` 表示原项目根目录，程序与参数都支持这两个占位符。例如，程序填写 `git`，参数填写 `status`，即可检查当前 worktree。执行脚本时，将解释器填为程序，将脚本路径填为参数。

命令在新的终端窗口中运行，工作目录为会话目录；输出和退出码保留到按 Enter 后关闭。Windows 使用 PowerShell，macOS 使用 Terminal，Linux 依次查找 `x-terminal-emulator`、`gnome-terminal`、`konsole`、`xterm`，找不到时需安装其中一种。启动失败会在应用内提示，启动后的运行错误显示在终端中。超过 10 秒未能确认启动时，先检查终端再重试。顶部配置和自定义命令执行仅桌面端可用；远程页面沿用已配置的内置按钮显隐和顺序。

常用快捷键（macOS 上把 Ctrl 换成 ⌘）：

| 快捷键 | 作用 |
| --- | --- |
| Ctrl+N | 回到首页，开始新对话 |
| Ctrl+K、Ctrl+Shift+F | 聚焦侧边栏搜索 |
| Ctrl+B | 显示或隐藏侧边栏 |
| Ctrl+F | 在当前对话或 Grok Bot 聊天中查找 |
| Enter / Shift+Enter、F3 / Shift+F3 | 下一个 / 上一个匹配（macOS 上也可用 ⌘G / ⌘⇧G） |
| Ctrl+Shift+D | 显示或隐藏变更面板 |
| Ctrl+, | 打开设置 |
| Enter | 发送；Agent 运行中时加入队列 |
| Ctrl+Enter | Agent 运行中时停止当前回合并立即发送 |
| Shift+Enter | 换行 |
| Esc | 停止当前运行 |

在整个桌面应用中，选中文字后右键选择 **复制**，或在聊天和其他可编辑输入框中右键选择 **粘贴**。文字会插入光标位置或替换选区；在聊天输入框中粘贴截图会添加附件，不会自动发送消息。这些应用右键菜单仅用于桌面端，远程页面沿用现有浏览器行为。

输入框用来选 CLI、模式和模型，也可以打开完全访问（`--force`）。首页上的 CLI 用于新建对话。对话里切换 CLI 时，已经显示的记录保留，下一条消息会用所选 CLI 新开一段会话，并带上已有对话作为上下文。这个选择会记成设置里 CLI 页的默认值。完全访问会让 CLI 在不逐条确认的情况下执行命令。对 Claude 来说，完全访问是 `bypassPermissions`；不开完全访问的 Agent 是 `acceptEdits`，改文件会自动通过，命令仍会询问。Ask 保持 Claude 的默认权限模式，应用会拒绝改文件和执行命令的请求。沙箱（`--sandbox`）在设置的「默认值」里：遵循 CLI、启用或禁用，只作用于 Cursor，不是输入框上的开关，Claude 不使用它。首页上，新建的对话还可以在项目目录和隔离的 git worktree 之间切换。Cursor 用 `--worktree`，随后在 CLI 报告的目录里继续；Codex 和 Claude 的 worktree 由本应用创建，项目必须是有提交的 git 仓库。

同一段对话里，CLI 进程在应用开着且上一轮正常结束时会保留。状态行只在真正新开进程时显示正在启动，否则显示处理中。

Cursor 回合如果以 `Error: RetriableError: [unavailable] HTTP 502` 或 `Error: RetriableError: [canceled] http/2 stream closed with error code CANCEL (0x8)` 结束，应用会在同一会话里自动发送一次「继续」，并保留仍在运行的 CLI 进程。进程若已经退出，则用已保存的会话重新加载后再发送。这次继续若再次失败，才显示错误。代理或 VPN 仍可能让第二次失败。

Codex 回合如果以 `Selected model is at capacity. Please try a different model.` 结束，应用会在同一会话里自动发送一次「继续」，并保留仍在运行的 CLI 进程。进程若已经退出，则用已保存的会话重新加载后再发送。这次继续若再次失败，才显示错误。

在一段对话里输入 `/` 会打开命令菜单。方向键移动，Enter 或 Tab 选中，Esc 只关闭菜单，不会停止正在运行的回合。`/fork` 在本地分叉。需要参数的命令会填成 `/名称 `，并在输入框下方显示提示，再按 Enter 发送。没有参数的命令会立刻执行。列表里还有 CLI 通过 ACP `available_commands_update` 宣告的命令。已有 CLI 会话的对话，第一次输入 `/` 会加载该会话，以便列出这些命令。新对话和首页不启动 CLI，而是复用这个 CLI 上一次宣告的命令列表，并记在本机；还没有任何列表时不显示菜单。下一次真实会话会刷新这份列表。使用 Cursor 或 Codex 时，菜单还会直接列出工作目录 `.agents/skills` 和 `~/.agents/skills` 中的 Skill（同名时项目内的优先），不用等 CLI 宣告，第一次输入 `/` 就能看到；每次输入 `/` 都会重新读取这两个目录。选中 Skill 会填成 `/名称 `，可补充说明后按 Enter 发送。CLI 宣告了同名命令时以 CLI 的为准。Claude 不读取 `.agents`，因此不列出这些 Skill。以 `/` 开头但没有匹配项的文本仍按普通消息发送。

Agent 运行时可以继续输入后续指令。按 Enter 会把草稿（连同附件）加入这段对话的队列，队列显示在输入框上方，可以连续排多条。每条消息记住加入队列时选的模式、模型和权限，行首显示 Agent、Plan 或 Ask 标签。拖动每行左侧的手柄可以调整顺序。每一条都可以编辑（放回空的输入框）、立即发送或删除。本轮正常结束后，队列中的消息按顺序自动发出。如果 Plan 回合产出了方案，队列会先等待：你审完方案后，等一个 Agent 回合（例如点**执行计划**）正常结束，队列再继续。中间用 Ask 或 Plan 追问不会让队列继续；点某一条的**立即发送**可以跳过等待。按 Ctrl+Enter（macOS 上是 ⌘+Enter），或点某一条的**立即发送**，会停止当前回合并优先发送这条消息，其余消息在它之后继续。以下情况会暂停队列：手动停止、本轮出错、排队消息发送失败。发送失败的消息会带着错误原因回到队首。点任意一条的**立即发送**即可继续。`/fork` 不能排队。队列由桌面端保存，所以其他窗口和远程页面看到的是同一份队列；退出应用后不保留。

项目分别记住 Cursor、Codex 和 Claude 的模型。修改其中一个 CLI 的模型或常用模型列表，会保留另外两个 CLI 的选择。

模型选择器还会按 CLI 和模型分别记住上下文长度、思考强度（含 Thinking）及 Fast 开关。Claude 把上下文和思考强度写成独立参数，例如 `opus[context=1m,effort=high]`。Cursor 的完整规格（例如 `grok-4.7[context=500k,reasoning_effort=high,fast=true]`）同样在会话建立后分别设置基础模型、上下文、思考强度和 Fast。如果 CLI 在设置其中一项时报告当前没有 ACP 模型，会重新选择基础模型并再设置一遍这些参数。把这一整段 id 传给 `--model` 时，CLI 会拒绝并打印全部模型名。在已有的 Cursor 对话里改选 Auto 时，会在会话上明确选择 `auto`，不会沿用上一个模型；如果 CLI 无法切回，这条消息会报错，下一条消息会以 Auto 新启动 CLI 进程。Codex 的标准速度仍用 `gpt-5.4[high]` 这种 id；适配器宣告支持 Fast 的模型会多出 `gpt-5.4[reasoning_effort=high,fast=true]`，会话建立后分别设置基础模型、思考强度，以及适配器的 `fast-mode`（`on` 或 `off`）。同一别名如果另外列出了 `[1m]`，不带上下文的那一项会标成 200K。旧版本保存的 `sonnet[high]`、`opus[1m][high]` 仍会选中对应的模型和思考强度。选择后立即保存，无需发送消息；切换回该模型或重启应用后再次选择时，会恢复它上次的配置。切换到常用模型、新建对话、切换项目或 CLI，以及设置页的默认模型，都会以该模型最新保存的配置为准，而不是项目或默认模型上次记录的旧档位。这些偏好保存在 `state.json` 中，桌面端与远程页面共享。已有对话保留自己的模型配置，打开旧对话不会覆盖这些偏好。如果 CLI 不再提供某个配置组合，选择器会使用当前可用的变体。鼠标悬停在模型按钮、列表中的模型或设置里的常用模型上时，显示该模型的公开 API 标价（美元 / 百万 token），有 Fast 或长上下文费率时一并列出。Auto 和价目表没有的模型显示未定价。

打开或刷新对话时，历史加载期间收到的流式消息会合并保留。CLI 返回空历史时不会覆盖本地对话。删除对话、修改 CLI 配置或退出应用，也会停止尚在预加载会话的 CLI 进程。

Git 页签显示工作区的实际内容；仓库尚无提交时，也会包含暂存后继续修改的内容。diff 视图会保留形似补丁头的正文（例如 SQL 的 `--` 注释），正确显示所属文件和增删行数。

变更面板的「本对话编辑」「快照差异」和「Git 差异」页签将二进制文件集中到列表末尾的「二进制文件（N）」分组，默认连文件名一起收起。点击分组标题（或聚焦后按 Enter／空格）显示文件名，再次点击收起；顶部文件总数和增删统计始终包含这些文件。三个页签分别记住本次打开面板时的展开状态，刷新列表不会收起分组；切换对话或重新打开面板后恢复默认折叠。

对话中每轮回复下方的修改文件列表也采用相同的二进制分组，默认隐藏组内文件名。每轮可以独立展开或收起，文件总数和增删统计始终包含二进制文件；文本文件仍直接列出，点击文件名查看差异。

文件名太长被截断时，鼠标悬浮在文件名上可查看完整路径；右键文件行可「复制路径」或「复制文件名」。对话内的修改文件列表和变更面板的三个页签都支持。

每轮回复下方的文件列表与「本对话编辑」只统计能归属到成功工具调用的修改。CLI 返回的逐文件补丁优先保存；明确成功的编辑工具若只有目标路径，仍列出文件，但显示「差异不可用」，不猜测增删行数。预览、拒绝、失败及未完成调用不计入，普通终端 `git diff` 输出也不作为修改证据。没有逐文件执行证据的 Python、PowerShell 等脚本修改只通过快照查看。同一文件的多次编辑按调用顺序展示，增删数累计已记录操作，并非当前工作区的净差异。外部软件后续修改文件或提交代码不会改变已保存的工具补丁。

右侧新增「快照差异」页签，单独查看每轮运行前后的工作区内容，可能包含其他软件的修改。默认跟随最近完成的一轮；通过「查看轮次」选择历史轮次后保持选择，选择「最近完成的一轮」恢复跟随。运行中的轮次在结束后才显示结果，手动停止或异常退出时成功采集的快照也会保存。空差异显示「本轮没有快照差异」，没有采集记录则显示「本轮未记录快照」。此页只读取已保存的差异，没有重新扫描按钮；查看当前未提交改动请使用「Git 差异」。切换快照轮次会收起二进制分组；切换对话或重新打开面板后，轮次选择恢复默认。

工具记录和工作区快照分别保存，重启、分叉和同步 CLI 历史后仍可查看。旧快照继续显示在「快照差异」，不会混入代理修改列表；旧工具记录仅从明确成功的结果恢复，缺少证据时不推断，也不根据当前磁盘追补历史。工具补丁单文件最多保存 256 KiB，每轮合计 16 MiB，超限时保留文件记录并显示「差异不可用」，不保存截断补丁。

Git 仓库使用 Git 跟踪和未忽略的普通文件。**非 Git 目录也支持快照，无须安装 Git 或初始化仓库**：递归读取工作目录中的普通文件，自动跳过版本控制元数据及 `node_modules`、`.venv`、`__pycache__`、`.cache`、`dist`、`build`、`out` 等常见依赖、缓存和构建目录；前 40 个按名称排序的直接子目录中已有的 Git 仓库会单独使用 Git 的忽略规则，避免重复统计。快照最多读取 5000 个文件、单文件 256 KiB、合计 16 MiB；普通目录遍历还限制为 1000 个目录、20000 个目录项和 20 层深度。跳过符号链接、子模块和超限文件，编辑工具记录仍可显示这些文件的差异。初始遍历不完整时，不会把之前未读取的文件猜成新增文件。

旧会话没有快照时，不会从显式 `git diff` 命令的保存输出恢复快照或推断代理修改；没有记录的历史差异无法追补。

Markdown 中标记为 `mermaid` 的代码块会显示为图表，历史会话和远程界面同样支持。图表跟随深浅色主题，可通过「查看源码」和复制按钮查看、复制原始 Mermaid 文本。加载期间或语法无法渲染时，会保留源码供查看。

关闭完全访问时，工具权限请求会显示选择卡，等待明确允许或拒绝；跳过或停止任务不会授予权限。Claude 对部分不受完全访问覆盖的操作仍会要求确认，这些请求也会显示选择卡。

### 退出应用

本机有正在启动、执行或等待权限确认、问题回复的会话时，退出应用会弹窗确认。选择 **取消** 会保留应用和会话继续运行；选择 **停止会话并退出** 会停止这些会话后退出。没有未结束的会话时直接退出。通过远程页面发起的本机任务也受同样保护；关闭远程网页不会退出主机应用。

在 macOS 上，关闭窗口后应用和会话继续在后台运行，退出应用时才会弹窗确认。

### 皮肤与动态背景

打开 **设置 → 外观与历史 → 外观 → 皮肤**，选择默认、磨砂或流光，也可自定义背景色、面板色、文字色、强调色、面板不透明度（0–100%）、模糊半径（0–40 px）、背景遮罩和图片/视频缩放。未覆盖的颜色继续跟随浅色、深色或系统主题。修改即时预览，点击 **应用皮肤** 后保存；**取消预览** 或离开外观页会还原未应用的修改。**另存为皮肤** 创建命名预设；修改已有自定义皮肤后应用会更新它。内置皮肤不可删除，恢复默认后也需应用才会保存。

桌面端支持选择图片（PNG/JPEG/WebP/GIF/BMP/SVG）、MP4/WebM 视频、Web 项目目录、HTML 入口或 Wallpaper Engine 的 `project.json`。视频静音循环播放，具体编码兼容性取决于 Electron。Windows 点击 **刷新 Wallpaper 壁纸库** 自动扫描多个 Steam 库中的已下载创意工坊、本地和内置项目；各桌面平台也可手动添加壁纸库或项目目录。列表支持搜索与类型筛选，Scene、应用壁纸、损坏或文件缺失的项目会显示原因，不能应用。

无需让 Wallpaper Engine 持续运行。素材引用原文件，不复制内容；移动、删除文件或取消创意工坊订阅后，可能需要通过 **选择文件 / 重新定位** 或 **选择 Web 项目** 重新选择。移除背景引用、删除皮肤均不会删除原文件。加载失败会回退到主题底色，并显示重试按钮和设置提示。

Web 壁纸在隔离框架中运行，不能调用应用 API、联网、创建子框架或 Worker。支持普通本地 HTML/CSS/JS/WebGL，以及默认属性、布尔/滑块/颜色/选项/文本属性调整、30 FPS 提示和暂停通知。Web 颜色属性使用 Wallpaper Engine 的格式：三个以空格分隔的 0–1 RGB 值。首版不实现实时音频采集与响应、桌面媒体信息、硬件接口或外部文件/目录属性，依赖这些能力的壁纸可能无法正常运行。隐藏或最小化时暂停视频、卸载 Web 实例；恢复显示会重新加载 Web。系统启用减少动态效果时，有预览图则显示预览，否则显示主题底色；流光改为静态渐变。

远程浏览器仅同步配色、透明度和模糊，不管理、下载或播放桌面背景。皮肤配置保存在 `data/state.json`，仅桌面使用的文件引用和手动添加的壁纸库目录保存在 `data/skin-sources.json`，见 [数据存储](data-storage.zh-CN.md)。

### 外观与历史

打开 **设置 → 外观与历史**，通过顶部的 **外观 / 顶部按钮 / 历史** 切换设置。外观页将界面和文字显示分组：主题卡片可直接选择浅色、深色或跟随系统，文字预览随字体和字号即时更新。顶部按钮页单独管理按钮顺序和自定义命令；历史页管理已归档对话的显示，并提供 CLI 历史导入入口。远程页面只显示外观和历史两项。

### 界面语言

打开 **设置 → 外观与历史 → 外观 → 语言**（英文界面为 **Settings → Appearance and history → Appearance → Language**），选择 **跟随系统**、**简体中文** 或 **English**。默认跟随系统：桌面端操作系统语言为中文时使用简体中文，其他语言使用英文。选择保存在 `state.json` 中，桌面端与远程页面共用该设置；跟随系统时也统一使用桌面端的系统语言。切换立即生效，无需重启应用或中断正在运行的会话。

导航、设置、弹窗、工具摘要、用量说明、日期、相对时间和应用系统通知均支持中英文。新生成的应用提示和自动会话标题保留文案标识，之后切换语言也会更新；用户自定义名称、消息、模型回复、CLI 原始输出，以及没有文案标识的旧历史文字保留原文。

### 字体与字号

打开 **设置 → 外观与历史 → 外观**，可以修改字体和字号。选择系统默认或常用字体，也可以输入设备上已安装的字体名称；字体不可用时回退到系统字体。字号范围为 **10–24 px**，默认为 **13.5 px**；界面文字、聊天内容、输入框和代码字号按比例一起调整，代码保留等宽字体。

修改立即生效，保存在 `state.json` 中，重启后保留。桌面端与远程页面共享这些偏好，实际可用的字体取决于各设备安装的字体。

## Grok Bot

点击侧边栏「项目」上方的 **Grok Bot**，可以和 Cursor 账号下的 [Grok Bot](https://cursor.com/docs/grok-bot) 对话。左栏列出你的 Bot，选中一个即可查看对话并发送消息。这里的对话和 Grok Bot 应用里是同一个，Bot 的记忆和工具都会保留。

- **Bot 列表**：公共 API 不提供列出 Bot 的接口。列表合并两部分：Grok Bot 桌面端缓存在本机的 Bot 列表（`<appData>/Grok Bot/sand-client-persistence`），以及你在 **设置 → Grok Bot** 中手动添加的名称。缓存里的 Bot 排在前面；手动名称已在缓存中时只显示一次。没有安装 Grok Bot 桌面端时，手动添加的名称照样显示。群聊和在 Grok Bot 侧边栏中隐藏的 Bot 不会显示。在 Grok Bot 里新建或改名 Bot 后点击刷新。手动名称可以在设置里删除，也可以点它那一行的 ×；这只会从本应用移除。
- **新建 Bot**：点击列表顶部的 **+**，输入名称。应用通过 API 打开这个名称，账号里没有同名 Bot 时会新建，然后把名称加入手动列表并选中。列表里已有同名 Bot 时，会先询问是否改为打开已有的那个，因为 API 按名称查找，不会再新建一个。
- **认证**：请求发往 `https://api.cursor.com/v0/grokbot`，使用 **设置 → CLI → Cursor** 中的 API Key；设置为空时使用环境变量 `CURSOR_API_KEY`。浏览器登录不能用于这里。可用 `CURSOR_API_BASE_URL` 覆盖 API 地址。
- **消息**：只显示你发的消息和 Bot 发给你的消息，不显示 Bot 内部的工作过程。Bot 处理中时每 1.5 秒刷新一次，可以中断当前这一轮；要等 Bot 处理完才能发下一条。空闲时每 10 秒检查一次新回复。
- **加载**：在 Bot 之间切换，或离开 Grok Bot 页面再回来时，已经加载过的消息会立即显示，只获取之后的变化。重启后第一次打开，会先显示这台电脑上保存的消息，再只获取更新的部分；Bot 的 API 会话 id 也会保存，省去较慢的按名称查找。对话很长、保存的副本被截短时，会在后台加载一次完整历史。如果保存的位置无法继续（API 拒绝、Bot 被重建，或 API Key 换成了另一个账号），会重新加载完整历史。
- **名称**：API 按名称查找 Bot。读取、发送和中断只会发送列表里的名称（缓存列表加手动名称）；只有「新建 Bot」会发送新名称。手动添加的名称如果在账号里不存在，第一次打开时会新建一个同名 Bot，所以请准确填写。如果两个 Bot 同名，界面会提示这段对话可能属于其中任意一个，建议在 Grok Bot 中改名。
- **文件**：API 返回的消息不含文件，发送文件的那条消息没有文字。对于缓存列表里的 Bot，应用读取 Grok Bot 桌面端缓存的该 Bot 对话记录，按序号、类型和时间对齐消息，再按 SHA-256 在 `<appData>/Grok Bot/attachment-image-cache` 中查找文件内容（Bot 的文件以 SHA-256 命名）。找到的图片（包括 SVG）用 `<img>` 显示，SVG 里的脚本不会执行；文件不会作为标记直接插入页面。每个文件可以另存为，也可以在文件夹中显示缓存文件。缓存里没有时，会显示带文件名的卡片，提示在 Grok Bot 应用中下载；轮询时会再检查最近的消息，卡片上也有「重新检查」按钮。手动添加的 Bot 没有缓存的对话记录，发送文件的消息只显示这张卡片。**这依赖 Grok Bot 桌面端未公开的本地缓存格式，Grok Bot 更新后可能失效。** 在远程浏览器中，预览和下载通过远程链接获取（每个文件最多 10 MiB）；在文件夹中显示只能在电脑上使用。

## Plan 模式

Cursor 不向 ACP 客户端提供 AskQuestion 工具。Codex 的 Plan 是协作模式（`collaboration_mode=plan`），保留所选的 Agent 权限配置，让确认执行后的实现阶段继承完全访问设置；规划期间，应用仍拒绝明确的文件修改权限请求。适配器若无法启用 Plan 或应用所选权限，本轮会报错停止。它不是 Cursor 的 `modeId: plan`。Claude 的 Plan 是适配器的 `plan` 权限模式。三种 CLI 的 Plan 消息前都会附一段说明，用 `<agent_desktop_client>` 标签包住。导入 CLI 历史时会去掉这个标签。这段说明要求模型这样工作：

- 需要选择时，模型输出语言标记为 `questions` 的围栏代码块，正文是 JSON。界面把它画成选项卡片，并为每道题自动添加「其他（手动输入）」。选中后显示多行输入框；单选题中与已有选项互斥，多选题中可与已有选项同时选择。选中「其他」后须填写非空白内容才能继续；切换选项会保留输入草稿，但取消「其他」后不发送该文字。按继续后，已有选项和手动回答一起作为下一条消息发出。跳过则让模型自行判断。只有最新一轮卡片可以提交。原生 ACP 权限卡片仍只提供固定选项。
- 需求明确后，Cursor 使用 CreatePlan，Codex 和 Claude 各自给出方案，生成名称、摘要和 Markdown 正文。界面显示方案卡片：名称、摘要、待办，以及可展开的完整方案。Cursor 还会提供「打开方案文件」（`~/.cursor/plans/*.plan.md`）。没有这个文件时，Codex 和 Claude 会隐藏该按钮。
- 「执行计划」把输入框切到 Agent 模式，并发送一条消息去实现该方案。只有最新的方案显示这个按钮。

Codex 在完成计划后还会询问是否执行。确认卡跟随应用语言设置显示中文或英文。选择「是」后，当前回合、已保存的对话和输入框会在开始实现前同步切换到 Agent，并保留完全访问设置；开启完全访问时，实现阶段的命令和文件修改不会再弹额外审批卡。选择「否，先修改计划」后会出现多行输入框，填写非空白修改意见后才能继续；切回「是」会保留草稿，但不会发送该文字。选择「否」会拒绝执行，并在当前回合结束后，把修改意见作为同一会话的下一条 Plan 消息发送给 Codex；已提交的意见会保存在历史中。跳过或停止不会批准执行或发送修改意见。其他原生 ACP 权限卡保持固定选项。

在 ACP 下，CLI 会自动批准模型发起的 SwitchMode，并且不通知客户端。如果 Cursor 或 Claude 在一轮 Plan 中切换了模式，应用会立刻把会话模式设回 Plan，避免它开始改文件。

## 功能细节

- 多项目侧边栏：添加、重命名、排序、折叠、搜索对话。搜索匹配标题、预览和项目名
- 分叉对话：可从标题栏、侧边栏、某条消息，或发送 `/fork` 开始，复制的历史会作为后续续聊的上下文
- 对话里的斜杠命令：输入 `/` 会列出 `/fork`、CLI 宣告的命令，以及 Cursor / Codex 下 `.agents/skills` 中的 Skill。`/fork` 在本应用内执行，其他命令作为下一条消息发出
- 三种模式：Agent（可改文件、执行命令）、Plan（只读方案，可点选回答提问、一键执行计划）、Ask（只读问答）
- 桌面与远程页面均支持选择文件、拖拽文件和粘贴截图；附件可以与文字一起发送，也可以单独发送
- Codex 后台子代理在回复输出期间完成时，Markdown 仍保持完整；旧历史中被这类通知拆开的回复会自动合并显示，代码块和选择卡片也能正常渲染。问题和选项中的换行会保留。
- 回复中的粗体兼容中文标点与汉字相邻的写法，例如 `这是**“重点”**内容`、`这是**重点：**内容`；完整计划正文使用相同的渲染方式。代码、转义星号和复制的消息原文保持不变。
- 按 ACP 消息 ID 保留进度说明与最终回复的边界，避免文字粘连导致 Markdown 围栏和选择卡片无法识别。加载旧 Codex 历史时，只有原始会话日志确认了消息的精确拼接内容，才恢复缺失的段落换行。
- 展开 Codex 命令可查看输出和退出码，失败命令及已保存的对话同样支持；没有输出时会明确提示。MCP 调用显示工具名称和结果，不会因错误字段为 null 而误报失败；旧对话会纠正 MCP 工具分类，并在原生 Codex 记录可用时按调用 ID 恢复真实状态。
- 回复里的本地文件链接（包括图片和 HTML 预览）会通过桌面系统默认程序打开。支持 Windows 路径、本机 `file:` 链接及相对路径；相对路径以当前会话的工作目录为基准，兼容 worktree。打开失败会显示错误。远程页面点击本地文件时会在宿主桌面打开并提示，网页链接则在远程浏览器打开。
- 悬浮界面中的任意超链接可查看完整地址，右键选择 **复制链接**。桌面端选中文字时，右键点击链接会提供 **复制**，复制当前选区；没有选区时提供 **复制链接**。网页显示和复制完整 URL；本地文件使用解码后的完整路径，相对路径按当前会话工作目录或 worktree 解析，源码行列后缀不计入文件路径。复制链接使用当前查看设备的剪贴板，并提示成功或失败。
- 模型选择：Cursor、Codex 与 Claude 各自记住常用模型、默认模型，以及每个模型的上下文长度、思考强度和 Fast。Codex 按每个模型自己的档位列出思考强度，例如 Astra 的 Ultra，并且只在该模型宣告支持 Fast 时提供 Fast 变体，会话里写成 `fast-mode` 的 `on` 或 `off`。Claude 把上下文和思考强度写成模型 id 上的独立参数，例如 `opus[context=1m,effort=high]`，每个模型保留适配器为该模型宣告的思考档位。Cursor 在会话建立后把完整规格拆成基础模型和各项参数再设置，例如 `grok-4.7[context=500k,reasoning_effort=high,fast=true]`。若 CLI 报告当前没有 ACP 模型，会重新选择基础模型并再设置一遍参数。旧 id（如 `sonnet[high]`）仍能解析。每个项目会记住自己在该 CLI 里上次选的模型。悬停模型可查看同一套公开标价
- 新建的对话可以在隔离的 git worktree 中运行。Cursor 使用 CLI 自带的 `--worktree`，随后在 CLI 报告的目录里继续会话；Codex 和 Claude 由本应用在项目 HEAD 上创建 worktree 和新分支 `agent-desktop/<名称>`，未提交的改动不会带过去
- 变更面板有两个页签：本对话编辑过的文件，以及当前工作目录的 git 分支、状态和 diff
- 对话内查找：在对话或 Grok Bot 聊天中按 Ctrl+F（macOS 为 ⌘F）打开查找栏，正在输入框里打字时也可以；如果在消息或输入框里选中了文字，会自动填入。查找不区分大小写，输入时实时更新；**Aa** 区分大小写，**ab** 全词匹配。查找栏显示当前是第几个和总数，高亮所有匹配并突出当前匹配，同时把它滚动到中间。Enter / Shift+Enter、F3 / Shift+F3 或箭头按钮切换匹配。Esc 关闭查找栏、清除高亮，并把焦点放回原处。只查找消息区域：侧边栏、标题栏、输入框、按钮和变更面板不在范围内。界面上没有显示的文字也不查找：已结束回合里收在「已处理 · N 个步骤」下面的步骤、折叠的工具详情、思考内容和完整计划。展开后即可查找，打开着的查找会自动包含它们。回复流式输出或 Grok Bot 收到新消息时，查找结果随之更新，并停留在当前匹配。远程网页中 Ctrl+F 同样打开这个查找栏；其他页面不拦截浏览器自带的查找。高亮需要 Chromium 内核的浏览器（桌面端始终满足）；不支持时仍会计数并滚动到匹配
- 可调宽度：拖动侧边栏、变更面板或 Grok Bot 列表的内侧边缘即可调整宽度。侧边栏 200–480 px（默认 272），变更面板 320–1000 px（默认 460），Grok Bot 列表 180–400 px（默认 240）。双击边缘恢复默认宽度。边缘获得焦点时，方向键每次移动 16 px（按住 Shift 为 64 px），Home 和 End 分别调到最窄和最宽。窗口太窄时，打开的面板会先从变更面板开始收窄，让主区域至少保留 320 px；窗口变宽后恢复到你选的宽度。桌面端把宽度保存在设置里；远程页面在所用浏览器里单独保存自己的宽度，不会改动桌面端。窗口宽度小于 720 px 时使用窄屏布局，面板不能调整宽度
- 一轮任务结束后，在回复下方列出本轮修改的文件，点开可看 diff
- 任务结束时，回复下方显示本轮耗时、token、使用的模型，以及按公开标价估算的费用。Codex 的“本轮周额度”使用服务端归属于当前会话的累计额度统计，悬浮说明展示周额度、5 小时额度等读数及统计口径。通过 ChatGPT 登录的新回合还会显示“本轮预估周额度”，取本轮前后账号周额度已用百分比之差；数据缺失或统计未完成时会明确标注
- 从 `~/.cursor/chats`、`~/.codex/sessions` 和 `~/.claude/projects` 导入 CLI 历史，并按工作目录归入项目
- 已有会话用 ACP 的 `session/load` 续聊，也可以从 CLI 存储把记录同步回来。复制会话 ID 后，可在终端用 `agent --resume` 继续一段 Cursor 对话
- 任务结束时发送系统通知，点击通知回到该对话。不在当前画面上结束的任务会留下未读点
- 侧边栏底部、设置按钮上方显示 **正在进行** 和 **未读** 总数，统计所有项目及归档对话，每个对话在各项统计中最多计一次。出现新的待回答问题、权限选择或计划确认时，会话标为未读并更新未读点、未读跳转和任务栏角标，同时仍计入正在进行。窗口可见、具有焦点且内容加载完成后即清除未读，无须先回答；同一卡片的后续更新不会重复提醒，新问题会再次标为未读。Markdown 问题卡片在本轮输出结束后沿用结束未读流程。其他运行中的对话不计入未读；成功、失败和手动停止均沿用现有未读规则。已结束的对话也在上述查看条件满足后标为已读，最小化后返回同一对话也会清除未读；远程页面查看后会同步桌面计数。
- Windows 使用原生任务栏叠加图标显示未读数量：`1–99` 显示实际数字，更多显示 `99+`，未读归零时清除，侧边栏始终显示完整数量。位置由 Windows 控制，位于图标右下角，与右上角角标不同。叠加图标支持已固定或分组的任务栏按钮，不依赖可执行文件或快捷方式图标缓存。角标由主进程更新，最小化或关闭完成通知也不影响；显示或恢复窗口时重新应用，有未读时每 5 秒刷新，以便在任务栏创建或 Explorer 重启后恢复。若没有显示，请检查 Windows **任务栏设置 → 任务栏行为 → 在任务栏应用上显示徽章**；小任务栏按钮不支持叠加图标。不同显示缩放和任务栏配置仍需原生桌面目视验证。
- 主题：跟随系统、深色、浅色
- 语言：跟随系统、简体中文、English，即时切换并在重启后保留选择
- 字体与字号：系统默认、常用字体或输入已安装的字体名称；10–24 px（默认 13.5 px），修改立即生效并在重启后保留
- 设置按左侧分类切换：CLI、MCP、Skill、模型、用量、默认值、通知、远程控制、外观与历史。CLI 页分别检测 Cursor、Codex 与 Claude，并填写路径、API Key 和登录；登录右侧的「更新」按钮可更新对应的独立 CLI，显示进度和执行结果，完成后刷新版本与模型列表。模型页用 Cursor / Codex / Claude 页签分别配置常用模型和默认模型。MCP 和 Skill 页可在「本应用」与「本地所有」之间切换，后者直接管理各 CLI 在本机的原生配置。导入历史在「外观与历史 → 历史」页
- 用量：显示 Cursor 与 Codex 的账号额度（有则显示 5 小时、每周、每月窗口和下次重置时间）。Claude 的账号额度尚未接入。Cursor 模型和其他模型还会显示该池的实际 token 和账号返回的价格。其他模型只显示包含的 API 用量百分比。按需支出在同一行显示已用和上限，有明细时再显示 token，不重复总价。下面按最近 1 天、7 天、30 天汇总本机 token，分页列出全部历史会话的模型和累计消耗。本机费用中，Cursor 用 [Cursor 公开标价](https://cursor.com/docs/models-and-pricing)，Codex 用 [OpenAI API 公开标价](https://developers.openai.com/api/docs/pricing)，Claude Code 用 [Anthropic API 公开标价](https://platform.claude.com/docs/en/about-claude/pricing) 估算。Claude 按本轮记录的 API 模型 id 计价，不用选择器里的别名。估算金额不代表订阅账单。Auto、没有记录 API 模型的 Claude 别名，以及价目表没有的模型显示为未定价
- 远程控制：局域网扫码，或经 SSH 反向隧道从公网打开同一页面
